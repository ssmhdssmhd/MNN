# 更新日志

## v0.0.19 (2026-11-03)

- 「公告」改为自动显示当前版本的更新内容：直接读取仓库 `CHANGELOG.md`，按 App 运行版本匹配对应条目并格式化展示，版本升级后内容自动变化

- 移除旧的 `KZ/gonggao.txt` 公告源

## v0.0.18 (2026-11-03)

- 修复 API 服务「启动不成功、老是自动关闭」：
  - 退出对话页不再自动停止 API 服务（此前 `ChatActivity` 销毁时会强制 `stopService`，客户端连接随即断开）；服务改为前台服务常驻，模型会话在服务运行期间保持加载
  - 服务启动改为返回真实结果：记录/展示失败原因，不再「失败也显示运行中」；端口被占用或 Netty 未进入运行态时会自动重试（最多 5 次）
  - 设置保存、重置配置、重启按钮改为在运行中的服务内原地重启，避免「销毁服务 → 立刻重建」与 Netty 异步关闭竞争端口导致的启动失败
  - 请求模型加载失败时自动回退到 API 已选模型或首个本地模型，避免整次启动失败
  - 启动前若检测到旧的失效实例会先阻塞停掉再重新绑定端口
- 服务启动失败时通知栏显示具体失败原因，便于排查

## v0.0.17 (2026-11-03)

- 修复长上下文场景下 API 响应慢：请求历史中助手消息的历史思考内容（`<think>...</think>`）在送入模型前被剥离，避免客户端每轮重发推理内容导致上下文膨胀、每次重复 prefill。对 DeepSeek-R1 等多轮会话，prompt 体积可下降数倍
- 仅含思考内容、无正文的助手消息不再计入历史
- 剥离后历史前缀与上一轮缓存一致，Prompt Cache 更容易命中
- API 日志新增首字延迟（First token after N ms）与推理耗时、prompt/generated token 数，便于定位瓶颈

## v0.0.16 (2026-11-03)

- 修复 API 模型响应过慢：API 会话改为加载应用内已调优的模型配置（线程数、后端、精度等与聊天一致），此前使用默认配置导致明显更慢
- API 新建会话自动开启原生 Prompt Cache：多轮对话仅对新增内容做 prefill，不再每次请求重复处理完整历史，首字延迟与总耗时显著降低
- 流式响应不再逐 token 写入日志（日志采集会抓取堆栈，占用大量 CPU），避免与模型解码抢资源
- 日志采集先按标签过滤再抓取堆栈，降低整体日志开销

## v0.0.15 (2026-11-03)

- 在线搜索支持输入完整仓库 ID（`owner/repo`），自动校验来源并下载

## v0.0.14 (2026-11-02)

- 搜索结果新增「下载」按钮，支持下载进度显示；下载完成后模型自动出现在本地模型列表
- 支持直接粘贴仓库 ID（如 `owner/repo`、`MNN/xxx`、`taobao-mnn/xxx`）进行校验并下载

## v0.0.8 (2026-11-02)
